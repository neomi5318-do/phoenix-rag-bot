# הצ'אט לאתר הפניקס · גרסת האתר (Vercel)

זו הגרסה החיה: דף אחד שמדבר לפניקס, והצ'אט עצמו בבועה בפינה - בדיוק כמו שהוא ייראה באתר שלהם
אחרי שמדביקים שורה אחת בקוד: `<script src="https://makor-phoenix.vercel.app/widget.js" defer></script>`
הנתונים (איסוף, חיתוך, אינדקס) מגיעים מהשלבים שבתיקייה הראשית; כאן נמצא רק מה שרץ בשרת ובדפדפן.

## הארכיטקטורה בקצרה

```
 דפדפן                                    שרת (Vercel, אפליקציית Flask אחת)
 ─────────                                 ─────────────────────────────────
 widget.js  ── GET /api/ask ──────────────▶ "חימום": טוען מודל + אינדקס לזיכרון
            ── POST /api/ask {שאלה} ─────▶ 1. retrieval.py  חיפוש היברידי → 6 קטעים
                                             2. bot.py        פרומפט + כללים
                                             3. llm.py        Gemini / Groq ("מירוץ מגובה")
                                             4. bot.py        אימות ציטוט, מקורות, מוקד
            ◀── {סטטוס, תשובה, מקורות, מוקד}     5. insights.py   "לא נמצא" → דוח פערי תוכן
 insights.html ── GET /api/insights ──────▶ הדוח לצוות התוכן (Upstash Redis)
 public/faq.json   (שאלות נפוצות - קובץ סטטי, נבדק ידנית)
```

| קובץ | מה הוא עושה |
|---|---|
| `app.py` | השרת (Flask). נקודת קצה אחת: `/api/ask`. GET = חימום, POST = שאלה ותשובה |
| `lib/embedder.py` | הופך את השאלה לווקטור, עם multilingual-e5-base בגרסת ONNX מכווצת (בלי PyTorch) |
| `lib/retrieval.py` | חיפוש סמנטי + מילות מפתח (BM25), ומיזוג RRF |
| `lib/bot.py` | הפרומפט והכללים, אימות הציטוט, ניתוב למוקד |
| `lib/llm.py` | שרשרת המודלים, "המירוץ המגובה", Backoff ותקרת זמן |
| `lib/insights.py` | הדוח "מה חסר באתר": שומר שאלות שלא נמצאה להן תשובה, אחרי מחיקת מספרים ומיילים |
| `tests/test_llm_chain.py` | בדיקות לשרשרת המודלים (429, עומס, מכסה יומית, איטיות) בלי לשלוח בקשות אמיתיות |
| `data/` | הקטעים, הווקטורים שלהם, ו-10 המוקדים (אומתו מול עמוד "צור קשר") |
| `public/widget.js`, `public/widget.css` | הצ'אט עצמו - JavaScript רגיל, בלי ספריות: בועה, סמל מונפש (נח / קורא / עונה), תשובה שנכתבת מול העיניים |
| `public/index.html` | הדף: פתיחה, "שורה אחת באתר שלכם", מה הלקוחות מקבלים, הפיצ'ר המקורי, אמינות ובדיקות, ארכיטקטורה |
| `public/insights.html` | הדוח המלא לצוות התוכן |
| `public/eval.json`, `public/showcase.json` | תוצאות 30 השאלות, והתסריט מהאתגר כפי שהבוט החי ענה (נוצרים ב-`eval_web.py export` וב-`build_showcase.py`) |
| `public/faq.json` | השאלות הנפוצות |
| `public/fonts/` | הגופנים (Rubik, Suez One - רישיון OFL), בלי תלות ב-Google Fonts |

## ההחלטות החשובות, ולמה

**אין קישורים מומצאים.** המודל לא כותב כתובות. הוא מחזיר *מספר קטע*, והקוד בונה ממנו את הקישור.

**הפיצ'ר המקורי: דוח "מה חסר באתר".** האתגר ביקש שהבוט יידע להגיד "זה לא כתוב באתר". אנחנו שומרים את הרגעים האלה: כל שאלה שלא נמצאה לה תשובה נרשמת (בלי פרטים מזהים) עם האזור באתר שהכי קרוב אליה, ו-`insights.html` מציג לצוות התוכן מה חסר ואיפה. אם המסד לא מחובר, הבוט ממשיך לעבוד כרגיל.

**הקישור שמדגיש.** המודל מחזיר לכל מקור משפט קצר מהקטע. הקוד בודק שהמשפט מופיע **מילה במילה** בקטע, ואם לא, מוחק אותו. הקישור בנוי כ-`כתובת#:~:text=המשפט`. זו תכונה מובנית של הדפדפן (Text Fragments), שפותחת את העמוד באתר הפניקס כשהמשפט כבר מסומן בצהוב.

**המוקד הנכון.** 10 מוקדים הועתקו מעמוד "צור קשר", וכל טלפון ומייל נבדק בקוד מול הטקסט של העמוד. המודל בוחר את המוקד המתאים לנושא, והדפדפן מחשב לפי שעון ישראל אם הוא פתוח עכשיו.

**שאלה אישית = כרטיס מוקד.** המודל מתבקש לזהות שאלות כמו "האם הפוליסה **שלי** מכסה…". בנוסף, הקוד בודק את זה שוב עם ביטוי רגולרי, כי זה כלל שאסור לפספס.

**חיפוש בלי PyTorch.** אותו מודל אמבדינג של הגרסה הראשית, בפורמט ONNX מכווץ (כ-280MB במקום 1.1GB). כך הוא נכנס לשרת החינמי. הקטעים הומרו לווקטורים פעם אחת מראש, ובשרת רק השאלה עוברת המרה (כ-50 מילישניות).

**מירוץ מגובה.** בדרגה החינמית, Gemini מוגבל ל-20 שאלות ביום לכל מודל, ובשעות עומס הוא לפעמים איטי מאוד. לכן:
1. שולחים לראשון ברשימה.
2. אם הוא נכשל, עוברים מיד לבא בתור.
3. אם הוא איטי מ-3 שניות, שולחים **במקביל** גם לבא בתור, ולוקחים את מה שמגיע ראשון.

ברשימה Gemini ו-Groq לסירוגין. Groq עונה בדרך כלל תוך כ-2 שניות.

**שאלות המשך בלי קריאה נוספת למודל.** בשאלה כמו "ותוך כמה זמן?" מחפשים לפי השאלה הקודמת יחד עם הנוכחית, ובנוסף לוקחים את 2 הקטעים הכי מתאימים **מהעמוד שממנו ענינו בפעם הקודמת** (הדפדפן שולח את הכתובות). כך "ותוך כמה זמן מקבלים תשובה?" נענית "בתוך 30 יום" מאותו עמוד, כמו בתסריט של האתגר.

**שאלה אישית לא מקבלת "כן" או "לא".** "האם הפוליסה שלי מכסה?" תמיד מסומנת כאישית (גם כשהמודל חושב שאין מידע), נפתחת במשפט קבוע שמפנה לשירות הלקוחות, ומשפטים עם הבטחות ("נבדוק ונחזור אליך") נמחקים.

**המשפט המודגש מוכיח את התשובה.** הקוד בודק שהציטוט מופיע מילה במילה בקטע, *וגם* שהוא קשור למשפט הראשון של התשובה. אם לא, הוא בוחר את השורה בעמוד שהכי מוכיחה אותו (לא כותרות ולא שאלות).

**שאלות נפוצות.** התשובות נוצרו על ידי הבוט (`build_faq.py`), ואז נבדקו ותוקנו ידנית מול האתר. הן מוצגות בלשונית נפרדת, ולא במקום תשובה חיה.

## בדיקה

אותן 30 שאלות של הגרסה הראשית (`python eval_web.py full`), עם בדיקה מחמירה: **30/30** (22.10.2026).
- שאלת המשך חייבת לענות את התשובה שכתובה באתר ("30"), ושאלה אישית לא יכולה להתחיל ב"כן" או "לא".
- אחזור לבד, בלי מודל שפה (`python eval_web.py retrieval`): המידע הנכון נמצא בקטעים ב-19 מתוך 19 שאלות שיש להן תשובה.
- זמן תשובה חציוני: 3.6 שניות. התוצאות המלאות: `../eval/web_results.json`, ובדף עצמו (פרק "למה אפשר לסמוך עליו").
- `python tests/test_llm_chain.py` - בדיקות לשרשרת המודלים.

## העלאה ל-Vercel

New Project ← לבחור את הריפו ← **Root Directory: `web`** ← Environment Variables: `GEMINI_API_KEY`, `GROQ_API_KEY` ← Deploy.
לדוח "מה חסר באתר": Storage ← Upstash Redis ← Connect (נוספים לבד `KV_REST_API_URL`, `KV_REST_API_TOKEN`) ← Redeploy.
Vercel מזהה את Flask לבד (`app.py`), ומגיש את `public/` ישירות מה-CDN.

## עדכון תוכן

בתיקייה הראשית מריצים `collect_pages.py`, `chunk_pages.py` ו-`build_index.py` (האינדקס מתעדכן רק בקטעים שהשתנו). אחר כך כאן מריצים `python build_data.py`, ואז `python eval_web.py full` ו-`python eval_web.py export` כדי לוודא שהכל עדיין עובר.
